# KeyboardWaiter 0.11.0

Drag counting is now exact, and the one parameter that cannot be exact is yours to set.

- **Drags are counted precisely.** A drag has real boundaries — mouse down, drag, mouse up —
  so guessing them from a time gap was wrong. One press-drag-release cycle is now exactly one
  count, no matter how long the drag lasts or how quickly the next one follows. Buttons are
  tracked independently, and the state recovers if the event tap is interrupted mid-drag
- **New Settings window** (`Settings...` in the menu bar, or `Cmd+,`) exposes the move stroke
  gap in milliseconds, from 20ms to 5000ms. Changes take effect immediately — no restart, no
  re-granting Input Monitoring
- **Default stroke gap lowered to 200ms** (was 400ms), so nearby movements are less likely to
  be merged into one
- The settings window spells out what the value does and does not affect: clicks, drags and
  scroll gestures all have exact start/end events and ignore it, and Pointer Travel measures
  distance so it ignores it too

Cursor movement is the only pointer metric that remains an estimate — a bare event stream with
no "stroke started" signal anywhere in it — which is exactly why the threshold is now a setting
rather than a constant.
