# KeyboardWaiter 0.11.1

A performance fix. No behaviour changes, no new counters.

- **The status bar no longer asks the system for the permission status on every event.**
  `refreshTitle()` called `CGPreflightListenEventAccess()` once per keystroke, click and
  stroke, and that call measures ~7.8ms — so ordinary typing kept roughly 12% of a CPU core
  busy doing nothing but re-asking a question whose answer almost never changes. The status is
  cached now and refreshed only on the slow paths: the 15s timer, opening the menu, and the
  permission flows.
- **The menu bar title is only written when the text actually changes.** Once the count is
  abbreviated to something like `4.2k`, a hundred consecutive events produce the same string;
  each write was triggering a menu bar redraw.
- **The input view refresh is throttled to 10Hz.** `refreshData()` re-queries the database and
  rebuilds the calendar grid (~7ms) and used to run once per event while the window was open.

Measured on the `refreshTitle` path at 12 events/second: 1207ms → 0.2ms of CPU time per
10 seconds.
